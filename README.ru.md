# opencode-docker-panel

[![CI](https://github.com/victor-ochenin/opencodeDockerPlugin/actions/workflows/ci.yml/badge.svg)](https://github.com/victor-ochenin/opencodeDockerPlugin/actions/workflows/ci.yml)

Панель контейнеров Docker для бокового сайдбара OpenCode 2.

Плагин добавляет себя в слот `sidebar.content`, опрашивает `docker ps --all --format "{{json .}}"` и позволяет действовать с контейнером прямо из строки. Клик по строке открывает диалог с командами, которые docker принимает в текущем состоянии контейнера, и только `Down` спрашивает подтверждение.

English version of this file: [README.md](README.md)

![Панель Docker в сайдбаре сессии, диалог действий и окно логов](docs/demo.gif)

## Что показывает панель

```text
Docker (3)                                              <- клик сворачивает
• chroma      127.0.0.1:8000  127.0.0.1:8001            <- клик открывает действия
• socnot-db   0.0.0.0:5432->5432/tcp · socnot
```

Цвет точки зависит от состояния: зелёный для `running`, жёлтый для `paused` и `restarting`, красный для `dead`, приглушённый для остальных. Сначала идут запущенные, внутри — по убыванию `CreatedAt`, поэтому список не прыгает между опросами. Панель рисует только запущенные контейнеры: не больше пяти строк, первые пять в том порядке, в котором их отдаёт docker. Остановленным контейнерам строки не достаётся, поэтому вход в них — заголовок. У заголовка две работы, и он сам говорит, какая из них сейчас: когда показывать нечего, рядом горит `click for all` и клик открывает диалог со всеми контейнерами; когда строки есть, надпись исчезает, а клик сворачивает и разворачивает их. Выбор контейнера в диалоге открывает те же действия, что и клик по его строке. Строка `N more, click for all` стоит под строками и появляется только когда строки есть, если что-то ещё скрыто. В заголовке же видны `stale`, когда docker перестал отвечать, и `working`, пока идёт действие.

Пункт `Pin` в меню контейнера оставляет контейнер видимым независимо от состояния, и на запущенном он занимает место в бюджете из пяти строк, поэтому закрепив всё, видно всё. Закрепление хранит хост, поэтому оно переживает перезапуск TUI и действует во всех сессиях; пункт `Unpin` в том же меню снимает его. Закреплённые строки помечены `pinned` рядом с портами и проектом.

## Действия

| Состояние контейнера | Какие действия предлагаются |
|---|---|
| `running`, `restarting`, `paused` | `Restart`, `Stop` и `Down`, если контейнер принадлежит compose-проекту |
| `created`, `exited`, `dead` | `Start` |
| любое другое | ничего |

| Действие | Команда |
|---|---|
| Start | `docker start -- <имя>` |
| Restart | `docker restart -- <имя>` |
| Stop | `docker stop -- <имя>` |
| Down | `docker compose -p <проект> down` |

Разделитель `--` обязателен: имя контейнера может начинаться с дефиса, и без разделителя docker примет его за флаг. Точная команда показана в подписи каждого пункта, поэтому разрушительная не выглядит сюрпризом.

`Down` выполняет `docker compose down` для compose-проекта из лейблов контейнера: останавливает все контейнеры проекта и удаляет их сети. Тома остаются, о чём и говорит диалог подтверждения. Контейнеру без compose-проекта пункт не предлагается, и `buildArgs` его тоже отклоняет.

Результат каждого действия приходит тостом, а панель обновляется сразу, не дожидаясь следующего опроса. Пока команда выполняется, в заголовке горит `working` и повторные клики игнорируются, так что двойной клик не запустит две команды.

## Логи

Пункт `Logs` в том же меню перезаписывает содержимое окна логами контейнера, то есть логи и действия делят одно окно. Закрывается через `esc` или кликом по нижней строке.

Просмотр — это `docker logs --timestamps --tail 200 -- <имя>`, обновление раз в две секунды, пока окно открыто. Docker пишет потоки контейнера вперемешку, поэтому буферы разбираются отдельно и снова сливаются по времени: без этого лог читался бы сначала целиком из stdout. ANSI-последовательности и одиночные `CR` вырезаются, иначе терминал выполнил бы их как управляющие коды. Окно фиксированной высоты в пятнадцать строк прокручивается колесом мыши.

| Состояние панели | Что видно |
|---|---|
| Docker работает, есть контейнеры | `Docker (N)` и по строке на контейнер |
| Docker работает, контейнеров нет | `no containers` |
| Docker Desktop не запущен | `docker desktop not running` |
| Docker не установлен | `docker not installed` |
| `docker ps` не ответил вовремя | последние известные строки с пометкой `stale` |
| Нет прав на сокет Docker | `no permission to talk to docker` |

Остановленный или отсутствующий Docker — это нормальное состояние, а не поломка плагина, поэтому оно показывается приглушённой строкой, а не ошибкой. Любой неудачный опрос, будь то таймаут или мёртвый демон, сохраняет последние известные строки с пометкой `stale`; успешный опрос без контейнеров очищает список.

## Требования

- Рантайм OpenCode 2 со слотами плагинов (`opencode2`)
- `docker` в `PATH`: Docker Desktop на Windows, Docker Engine на Linux и macOS
- Node.js 22 или новее для запуска проверки парсера

## Структура

```text
tui.tsx       CLI-точка входа: регистрация слота сайдбара
panel.tsx     Solid-компонент: заголовок, строки, состояния, диалог действий
poll.ts       цикл опроса: хранит последние известные строки и таймер обновления
commands.ts   сборка и запуск команд жизненного цикла
logs.ts       чтение, очистка и упорядочивание строк лога
docker.ts     запуск docker ps, разбор и сортировка вывода
types.ts      типы контейнера и состояния, ограничение опций
scripts/      проверки парсера и команд
fixtures/     сохранённый вывод docker ps для проверки
```

Серверной точки входа здесь намеренно нет. Плагин работает только на стороне CLI, поэтому OpenCode не просит сервер его загружать и не требуется резолвить импорт `@opencode/plugin` во время работы. Точка входа экспортирует обычный объект с `id` и `setup`, типизированный как `Plugin.Definition`, а `Plugin.Context` подключается только типами, и такой импорт стирается при загрузке. Именно это доказывает правильность формы: claim слота, опции диалога, варианты тоста и токены темы проверяются по опубликованным типам, а не по локальной догадке.

Цвета берутся напрямую из `context.theme`: `text.base`, `text.muted` и `text.feedback.{success,warning,error}.base`. Они обязательны, типизированы как `RGBA`, поэтому цепочки фолбэков не существует и нечему расходиться с реальностью; хост, который перестанет их отдавать, ломает сборку, а не рисует не тот оттенок.

Строки панели только английские, документация двуязычная. Пакет не ставится из npm: он отдаёт точку входа `.tsx` и рассчитывает, что хост сам транспилирует её и предоставит `solid-js` и `@opentui/*`, поэтому они в dev-зависимостях.

## Установка

Скопируй файлы в конфиг-каталог OpenCode:

```text
~/.config/opencode/plugins/docker-panel/
```

На Windows это `%USERPROFILE%\.config\opencode\plugins\docker-panel\`.

```powershell
$src = "path\to\opencodeDockerPlugin"
$dst = "$HOME\.config\opencode\plugins\docker-panel"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item "$src\*.ts","$src\*.tsx","$src\package.json" -Destination $dst -Force
```

Зарегистрируй плагин в `cli.json`, иначе CLI не знает, что загружать:

```jsonc
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "plugins": [{ "package": "./plugins/docker-panel", "options": { "intervalMs": 3000 } }]
}
```

После этого перезапусти TUI.

## Опции

| Опция | По умолчанию | Примечания |
|---|---|---|
| `intervalMs` | `3000` | Интервал опроса, ограничивается диапазоном 1000..60000 |

## Проверка

```sh
npm run check
```

```text
parser checks passed
fixture: 3 containers -> chroma:running, postgres:running, worker-old:exited
live: kind=ok detail=- containers=2
```

Проверка на фикстуре подтверждает сортировку, разбор портов, нормализацию имён и устойчивость к битым строкам, извлечение compose-лейблов, точную команду для каждого действия, набор действий для каждого состояния, ограничение лимита строк и правило опроса, что неудачный запрос сохраняет последние строки. Затем делается один живой вызов `docker ps` и печатается его состояние. Для всего, кроме последней строки, не нужны ни Docker, ни запущенный OpenCode.

Проверка типов:

```sh
npm install
npm run typecheck
```

Проверка типов заодно проверяет плагин против хоста: `@opencode/plugin` и `@opencode/theme` стоят в dev-зависимостях только ради типов, поэтому ломающее изменение в API TUI-плагинов падает на `npm run typecheck`, а не при загрузке.

## Ограничения

- OpenCode 2 находится в бета-фазе, поэтому имена слотов и токены темы могут измениться; проявится это ошибкой типов, а не сюрпризом в рантайме.
- Хост не перерисовывает слот, когда меняется только реактивное значение, поэтому панель перемонтируется через новый claim слота, когда список контейнеров действительно изменился, и не чаще раза в десять секунд. Это обходное решение: оно сбрасывает свёрнутое состояние и закрывает открытое окно логов, а сам пробел с перерисовкой принадлежит хосту.
- Опрос порождает `docker ps` с интервалом. На машине с сотнями контейнеров подними `intervalMs` до 5000 или выше.
- Строк не больше пяти, и пять — константа, а не опция: на машине с тридцатью контейнерами панель покажет пять, а остальные останутся в диалоге. Единственный способ вывести шестой — закрепить его.
- Сам сайдбар не прокручивается, поэтому контейнеры за пределами пяти живут в диалоге, а не в панели.
- Выбранный лимит строк не запоминается между сессиями: это правка `cli.json` и перезапуск.
- Нет exec, работы с томами и образами, истории перезапусков. `Down` предлагается у контейнера, но действует на весь compose-проект. Окно логов — фиксированное окно поверх последних 200 строк, истории глубже нет.
- Действия только мышью; слой клавиш плагин не регистрирует.
